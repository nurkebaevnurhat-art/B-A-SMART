# B&A SMART — интернет-магазин смартфонов и аксессуаров

Премиальный интернет-магазин для Казахстана: новые, б/у и восстановленные смартфоны, планшеты, смарт-часы и аксессуары, халяльная рассрочка, личный кабинет и административная панель. Языки — русский и казахский, валюта — тенге (₸).

> **Статус: демонстрационная версия.** Каталог, цены и отчёты проверки — примеры. Онлайн-оплата работает только в тестовом режиме, заключение договоров рассрочки отключено. Перед реальными продажами выполните чек-лист в разделе [«Что нужно до запуска продаж»](#что-нужно-до-запуска-продаж).

## Что умеет магазин

**Покупателю**
- Главная в стиле референса: информационная полоса, шапка с логотипом по центру, мега-меню, выбор города, hero-слайдер из баннеров, подборки (популярные, новинки, новые, б/у, аксессуары, рекомендуемые), блок рассрочки с расчётом на реальном товаре, преимущества, проверка б/у, отзывы (только одобренные), FAQ, доставка и гарантия.
- Каталог с фильтрами (производитель, состояние, категория б/у, цена, память, цвет, совместимость, наличие, рассрочка), сортировкой, пагинацией, поиском; фильтры сохраняются в URL.
- Страница товара: галерея с увеличением, выбор цвета и памяти, характеристики именно этой модели, комплектация, гарантия, доставка, рассрочка, совместимые аксессуары, похожие модели, б/у этой модели, отзывы.
- **Б/у — каждый экземпляр отдельно**: уникальный номер (BA-U-1001), свои фото, корпус, экран, аккумулятор (или «не измерялась»), дефекты, ремонты, комплектация, гарантия и отчёт проверки по пунктам.
- Корзина (телефон + аксессуары в одном заказе), оформление с бронью б/у экземпляров, промокоды, способы доставки и оплаты.
- Личный кабинет: регистрация/вход по телефону или email, восстановление доступа, профиль, заказы и их статусы, избранное, заявки и графики рассрочки, поддержка.
- Русский и казахский интерфейс, PWA (установка на экран телефона), адаптивная вёрстка.

**Владельцу и сотрудникам (`/admin`)**
- Показатели, заказы (статусы с историей, трек-номер), платежи, покупатели, поддержка.
- Товары: создание, черновик → публикация → архив, варианты (SKU, цвет, память, цена, старая цена), фото (загрузка в БД или по URL), характеристики, совместимость, SEO.
- Б/у экземпляры: карточка, фото конкретного устройства, отчёт проверки, выставление в продажу.
- Остатки с журналом движений, категории и бренды, промокоды, баннеры, модерация отзывов.
- Настройки: контакты, информационная полоса, критерии состояния б/у, условия рассрочки, оформление заказа, способы доставки, очередь уведомлений.
- Сотрудники, роли (владелец / администратор / сотрудник) и разрешения, журнал административных действий.

## Технологии и архитектура

| Слой | Решение |
|---|---|
| Фреймворк | Next.js 15 (App Router), React 19, TypeScript |
| База данных | PostgreSQL + Prisma ORM (миграции в `prisma/migrations`) |
| Стили | Tailwind CSS + дизайн-токены (CSS-переменные из `src/config/brand.ts`) |
| Валидация | Zod — на сервере для каждого запроса и действия |
| Авторизация | Собственные сессии в БД: httpOnly-cookie для сайта и Bearer-токен для приложения; пароли — scrypt |
| API | Версионируемый REST `/api/v1` + OpenAPI 3.1 (`/api/v1/openapi.json`, `/api-docs`) |
| Тесты | Vitest (интеграционные, с настоящей БД) и Playwright (e2e в браузере) |

```
src/
  app/
    (shop)/          витрина: главная, каталог, товар, б/у, корзина, оформление, кабинет, рассрочка, инфо-страницы
    admin/           админ-панель (серверные компоненты + серверные действия в admin/_actions)
    api/v1/          REST API для сайта и мобильного приложения
  server/
    services/        бизнес-логика (каталог, корзина, заказы, оплата, рассрочка, авторизация…) — не зависит от React
    auth/            пароли, сессии, роли и разрешения
    admin/           обёртка серверных действий (проверка прав → валидация → аудит)
  components/        UI-компоненты и дизайн-система (components/ui)
  lib/               форматирование, i18n, клиент API, чистый расчёт рассрочки
  config/brand.ts    название, цвета и логотип — в одном месте
prisma/              схема, миграции, демо-данные (seed.ts)
tests/, e2e/         автотесты
```

Ключевые принципы:
- **Сервер не доверяет клиенту**: цены, наличие, скидки, стоимость доставки и итог пересчитываются при каждом заказе; если итог, который видел покупатель, отличается — заказ не создаётся (409).
- **Нет двойной продажи**: остатки списываются условным атомарным обновлением (`stock >= qty`), уникальный б/у экземпляр продаётся только если он свободен или забронирован этой же корзиной. При оформлении б/у бронируется на настраиваемое время (по умолчанию 15 минут). Отмена заказа возвращает товары в продажу.
- **Права проверяются на сервере** в каждом серверном действии и на каждой странице админки, а не только скрытием кнопок.
- Все постоянные данные — в PostgreSQL (включая загруженные изображения — таблица `MediaFile`), а не в файлах сервера.

## Быстрый старт (локально)

Нужны Node.js 20+ и PostgreSQL 14+.

```bash
# 1. Установить зависимости (скачает пакеты из npm)
npm install

# 2. Создать файл настроек из шаблона и указать DATABASE_URL и SESSION_SECRET
cp .env.example .env

# 3. Создать таблицы в базе (применяет все миграции из prisma/migrations)
npx prisma migrate deploy

# 4. Загрузить демонстрационные данные (товары, б/у, пользователи). Только для разработки!
npm run db:seed

# 5. Запустить сайт в режиме разработки → http://localhost:3000
npm run dev
```

Демо-учётные записи (пароль `Demo12345!` или значение `SEED_PASSWORD`):

| Роль | Логин |
|---|---|
| Владелец | owner@basmart.kz |
| Администратор | admin@basmart.kz |
| Сотрудник | staff@basmart.kz |
| Покупатель | customer@basmart.kz |

Полезные команды:

## База данных и миграции

- Схема — `prisma/schema.prisma`. Сущности: пользователи, роли, сессии, товары, категории, бренды, варианты, фото, б/у экземпляры, отчёты проверки, движения остатков, корзины, заказы, позиции, история статусов, платежи, события платёжного провайдера, доставка, промокоды, заявки и договоры рассрочки, графики платежей, избранное, отзывы, баннеры, настройки, обращения, журнал аудита, очередь уведомлений.
- Используются внешние ключи, уникальные ограничения (SKU, код экземпляра, номер заказа, событие провайдера), индексы и транзакции.

```bash
# Разработка: изменить schema.prisma и создать новую миграцию
npx prisma migrate dev --name описание_изменения

# Сервер/production: применить готовые миграции (данные не удаляются)
npx prisma migrate deploy

# Посмотреть данные в браузере
npx prisma studio
```

> ⚠️ `npm run db:seed` **очищает каталог и заказы** и загружает демо-данные. Никогда не запускайте его на боевой базе.

## Развёртывание (Vercel + PostgreSQL)

1. **База данных.** Создайте PostgreSQL в облаке: Neon, Supabase, Railway или Vercel Postgres (Neon). Скопируйте строку подключения (обычно с `?sslmode=require`). Для serverless рекомендуется строка через пулер соединений (pgbouncer) — у Neon/Supabase это отдельный «pooled» URL.
2. **Миграции.** С компьютера выполните один раз (и после каждого обновления схемы):
   ```bash
   DATABASE_URL="строка-подключения" npx prisma migrate deploy
   ```
3. **Vercel.** Импортируйте репозиторий на vercel.com → New Project. Framework определится автоматически (Next.js), команда сборки — `npm run build`.
4. **Переменные окружения** (Project → Settings → Environment Variables): `DATABASE_URL`, `APP_URL`, `SESSION_SECRET`, `PAYMENT_PROVIDER`, `NEXT_PUBLIC_DEMO_MODE`. См. таблицу ниже.
5. **Первый владелец.** На боевой базе не используйте сид. Создайте роли и владельца скриптом (существующие данные он не трогает):
   ```bash
   DATABASE_URL="строка-подключения" OWNER_EMAIL=you@shop.kz OWNER_PASSWORD='надёжный-пароль' npm run db:bootstrap
   ```
   Затем войдите на сайт и заполните каталог, доставку и настройки в `/admin`.
6. **Фото товаров.** Загружаются через админку и хранятся в БД (до 5 МБ на файл). При большом объёме фото позже можно перейти на объектное хранилище (Vercel Blob, S3) — достаточно изменить `src/server/admin/media.ts`.

## Подключение домена

1. Vercel → Project → Settings → Domains → добавьте `your-domain.kz` и `www.your-domain.kz`.
2. У регистратора домена (например, PS.kz, Hoster.kz) создайте записи, которые покажет Vercel: `A` для корня (обычно `76.76.21.21`) и `CNAME www → cname.vercel-dns.com`.
3. Дождитесь выпуска SSL-сертификата (автоматически) и обновите `APP_URL` на `https://your-domain.kz`, затем Redeploy.

## Переменные окружения

| Переменная | Обязательна | Назначение |
|---|---|---|
| `DATABASE_URL` | да | Подключение к PostgreSQL |
| `APP_URL` | да | Публичный адрес сайта (ссылки, sitemap, возврат с оплаты) |
| `SESSION_SECRET` | да | Секрет приложения (`openssl rand -base64 48`) |
| `PAYMENT_PROVIDER` | нет | `mock` (тест) или код реального провайдера после интеграции |
| `ALLOW_TEST_PAYMENTS` | нет | `true` — разрешить тестовую оплату на production (только демо-стенд) |
| `MOCK_PAYMENT_SECRET` | нет | Секрет подписи тестовых уведомлений |
| `NEXT_PUBLIC_DEMO_MODE` | нет | `false` — скрыть плашку «демонстрационная версия» |
| `SEED_PASSWORD` | нет | Пароль демо-пользователей при сиде |
| `TEST_DATABASE_URL` | для тестов | Отдельная тестовая база |

Секреты хранятся только в `.env` (он в `.gitignore`) и в настройках Vercel — не в коде.

## Резервное копирование

- **Облачная БД.** Включите автоматические бэкапы/Point-in-Time Recovery у провайдера (Neon — история веток, Supabase — ежедневные бэкапы и PITR на платных тарифах, Railway — бэкапы томов).
- **Ручной дамп** (рекомендуется ежедневно по расписанию и перед обновлениями):
  ```bash
  # Сохранить базу в файл (сжатый формат)
  pg_dump "$DATABASE_URL" -Fc -f backup-$(date +%F).dump
  # Восстановить в пустую базу
  pg_restore -d "$NEW_DATABASE_URL" --no-owner backup-2026-01-01.dump
  ```
- Храните копии вне основного провайдера (например, в отдельном облачном хранилище) и регулярно проверяйте восстановление на тестовой базе.

## Онлайн-оплата

Архитектура готова (`src/server/services/payments`):
- общий интерфейс провайдера: создание платёжной сессии → переход на страницу провайдера → **подтверждение только по серверному уведомлению (вебхуку)**;
- проверка подписи уведомлений, защита от повторной обработки (`PaymentEvent` с уникальным `provider+eventId`), сверка суммы с заказом, обработка успеха, отказа и отмены;
- заказ становится «Оплачен» только после подтверждения провайдером — переход покупателя на страницу «успеха» ничего не меняет;
- данные карт (номер, CVV, PIN) магазин не получает и не хранит.

**Сейчас подключён только тестовый провайдер `mock`** — страница `/pay/test/...` с кнопками «Успешная оплата / Отказ / Отмена». Реальные деньги не списываются.

Для боевых платежей нужно (вне кода): выбрать провайдера (кандидаты: **Halyk ePay**, **Kaspi Pay** (через партнёрский договор Kaspi), **Freedom Pay**, **CloudPayments Казахстан**), заключить договор интернет-эквайринга, получить тестовые и боевые ключи, проверить документацию API и реализовать `createSession`/`parseWebhook` в заготовке `src/server/services/payments/unconfigured.ts`. Условия и доступность API нужно подтвердить у провайдера — в коде нарочно нет «выдуманных» вызовов.

Уведомления по email/SMS (восстановление пароля и т.п.) сейчас попадают в очередь в БД (видна в «Настройки → Очередь уведомлений»). Для реальной отправки нужен SMTP или SMS-провайдер (например, Mobizon, SMSC.kz) — подключается в `src/server/services/outbox.ts`.

## Халяльная рассрочка

- Страница `/installment`: принцип, участвующие товары, полная согласованная цена, взнос, сроки, платежи, график, порядок оформления, документы, досрочное погашение и возврат, интерактивный калькулятор и форма заявки (ФИО, телефон, город, согласие на обработку ПДн — без загрузки документов).
- Расчёт — **без процентов на остаток, скрытых комиссий и штрафов**. Возможна только фиксированная наценка продавца по сроку, согласуемая до сделки (по умолчанию 0 %), — показывается отдельной строкой.
- Цена в заявке берётся сервером из каталога, а не из формы.
- В админке: условия программы, заявки и их статусы, договоры и графики (отметка платежей).
- **По умолчанию включён демонстрационный режим, а заключение договоров отключено.** Включить договоры может только владелец — после того как конкретную модель сделки проверят специалист по исламским финансам и юрист в Казахстане.

## REST API и мобильное приложение

- Документация: `/api-docs` (человекочитаемо) и `/api/v1/openapi.json` (OpenAPI 3.1 — для Swagger UI, Postman, генерации клиента).
- Формат: `{ data }` / `{ error: { code, message, details } }`; цены — целые тенге.
- Авторизация приложения: `POST /api/v1/auth/login` → `token`, далее заголовок `Authorization: Bearer <token>`. Гостевая корзина — заголовок `X-Cart-Token` (значение `token` из `/cart`).
- Бизнес-логика вынесена в `src/server/services` — её используют и страницы сайта, и API, поэтому изменения в админке сразу видны и на сайте, и в приложении (одна база, один backend).

План мобильного приложения (React Native + Expo) на существующем API: каталог, поиск, фильтры, товар, новые и б/у, аксессуары, избранное, корзина, оформление, кабинет и история заказов, доставка, рассрочка; далее — push-уведомления (Expo Notifications + таблица токенов устройств) и deep links на товары (`/product/{slug}`, `/used/{code}` — те же URL, что на сайте). Отдельная база для приложения не нужна.

PWA уже работает: манифест, иконки, service worker с офлайн-страницей — сайт можно установить на экран телефона.

## Фирменный стиль

- Название, цвета и короткое имя — `src/config/brand.ts` (цвета взяты из логотипа: сине-петролевый `#274E65` и оранжевый `#F07F04`). Все компоненты используют токены `primary`, `accent`, `ink`, `surface` и т.д.
- Логотип — `src/components/ui/Logo.tsx` (основная и компактная круглая версии, светлый вариант для тёмного фона), иконка сайта — `src/app/icon.svg`, иконки приложения/PWA генерируются в `src/lib/app-icon.tsx`.
- Тексты интерфейса — `src/lib/i18n/dict.ts` (ru/kk). Казахский перевод стоит вычитать носителю языка.

## Что нужно до запуска продаж

- [ ] Заменить демо-каталог реальными товарами, ценами и остатками; **загрузить реальные фото** (сейчас вместо фото — векторные иллюстрации с пометкой).
- [ ] Сверить характеристики каждой модели с данными производителя/региональной версии.
- [ ] Для б/у — фото каждого экземпляра и реальные отчёты проверки.
- [ ] Указать реквизиты, контакты и адрес в «Настройки магазина»; проверить юристом шаблоны «Условия покупки», «Политика конфиденциальности», «Обмен и возврат».
- [ ] Подключить платёжного провайдера (договор + ключи + реализация) или оставить только оплату при получении.
- [ ] Подключить SMTP/SMS для уведомлений.
- [ ] Проверить модель халяльной рассрочки у специалиста по исламским финансам и юриста; только затем выключить демо-режим и включить договоры.
- [ ] Сменить все демо-пароли, удалить демо-пользователей, задать `NEXT_PUBLIC_DEMO_MODE=false`.
- [ ] Настроить резервное копирование и проверить восстановление.
